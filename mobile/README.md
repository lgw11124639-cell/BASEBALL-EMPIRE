# BASEBALL EMPIRE · 모바일 오프라인 시험판

가상의 프로야구 리그 출범부터 세대 교체까지 관전하는 **유료 다운로드형 싱글플레이 게임**을 목표로 합니다. 경기 지시·직접 조작을 추가하지 않고 기존 화면과 게임 엔진을 재사용합니다.

## 현재 구현 범위

- 별도 Android 프로젝트와 앱 내부에 포함되는 게임 코드/스타일. 원격 사이트를 여는 설정은 없습니다.
- 로그인·회원가입·클라우드 클라이언트·웹 자동 업데이트를 모바일 번들에서 제외합니다. 기존 웹 서비스와 서버는 그대로 보존합니다.
- 기기 내부 IndexedDB 저장. 선수 64명, 경기 결과 8경기 단위와 나머지 최상위 필드를 분리하고, 직전 직렬화 결과와 비교해 변경 조각만 씁니다. 매일 전체 저장을 다시 읽지 않습니다.
- 변경 조각과 저장 포인터를 한 트랜잭션으로 커밋합니다. 현재/이전 두 세대만 유지하며, 실패 시 이전 커밋이 남습니다. 최신 조각이 손상되면 이전 세대 복구를 알리고, 모두 손상됐으면 덮어쓰지 않고 중단합니다.
- Android 백업은 시스템 파일 저장 창으로 앱 외부에 내보냅니다. JSON 백업 가져오기도 시스템 파일 선택 창을 사용하며 첫 화면에서도 실행할 수 있습니다. 네이티브 전송은 작은 UTF-8 조각으로 나누고, 취소·쓰기 실패 때는 완료로 표시하지 않습니다. Google/Apple 계정 연동과 자동 원격 백업은 없습니다.
- Android 앱은 인터넷 권한이 없으며, 웹 에셋은 외부 통신을 CSP로 제한합니다. 앱 삭제 시 내부 저장은 사라지므로 외부 백업이 필요합니다.

이는 **출시 후보가 아닌 개발 시험판**입니다. 앱 식별자 `com.baseballempire.game`와 서명 인증서의 공개 지문을 고정합니다. 설치 사용자에게 호환 업데이트를 제공하려면 이 ID와 서명 키를 유지해야 합니다. 기본 Android 아이콘은 임시입니다. 개인 서명 키는 소스·APK·공개 아티팩트에 포함하지 않습니다. 결제·스토어 등록은 아직 포함하지 않습니다.

## Windows에서 실행

Node.js 22 이상과 Android Studio(기본 SDK, JDK 21 이상)를 설치합니다.

```powershell
npm ci
npm run mobile:android
npm run mobile:open
```

Android Studio에서 Device Manager로 API 35 이상 가상 기기를 만듭니다. 앱의 유지 서명 키를 설정한 뒤 Run을 누릅니다. 첫 빌드에는 SDK/Gradle 다운로드를 위한 인터넷이 필요하지만, 빌드된 게임의 실행·계산·저장은 오프라인입니다.

개발 APK도 유지 서명 키가 필요하며 키 없이 임의 서명으로 빌드하지 않습니다. 소유자가 보관한 `signing.json`과 `.p12`를 복원해 사용합니다. 새 키를 만들면 기존 앱 업데이트가 끊어집니다. 명령행에서는 SDK 경로를 `android/local.properties`에 설정한 뒤 실행합니다.

```powershell
node scripts/build-signed-android.mjs C:\private\baseball-empire\signing.json
```

출력: `android/app/build/outputs/apk/debug/app-debug.apk`. 개발 APK는 유료 배포용 서명 릴리스가 아닙니다. 유료 출시에는 별도 보관하는 서명 키와 release AAB가 필요합니다. 키와 비밀번호는 저장소에 넣지 않습니다.

## 폰 없이 PC에서 흐름 검증

```powershell
npm run mobile:build
npm run mobile:preview
```

`http://127.0.0.1:4173`에서 새 리그 생성, 하루 진행, 새로고침 후 이어하기, JSON 백업과 복원을 확인합니다. 브라우저 저장은 Android 앱 저장과 별개입니다. 브라우저에서 외부 네트워크를 끊어도 진행됩니다. Android WebView의 속도·플러그인·강제 종료 내구성을 검증한 것으로 간주하지 않습니다.

```powershell
npm run mobile:test
npx playwright install chromium
npx playwright test --config mobile/playwright.config.mjs
```

4. 복수 저장 슬롯, 저장 형식 마이그레이션, 완성된 앱 아이콘과 개인정보/지원 문서를 준비합니다. 초기 화면 백업 가져오기는 0.3.0에 구현했습니다.
5. 최소/중급 실기기 테스트, 비공개 배포, 유료 정책·가격·연령 등급·서명 키 관리 후 스토어에 제출합니다.

기존 서버는 사용자가 명시적으로 종료를 요청하고 저장 이전 검증을 마친 뒤 별도 작업으로 종료합니다.

GitHub Actions의 **Build offline Android trial → Run workflow**에서도 동일한 검사를 거쳐 개발 APK를 만들 수 있습니다. 성공한 실행의 `baseball-empire-offline-trial-apk` 아티팩트를 내려받습니다. 이는 시험용 다운로드이며 스토어에 게시하지 않습니다.

0.2.0 검증에는 비시즌/정규경기의 Worker 대 원본 엔진 결과 일치, 지연된 계산 중 화면 반응·정지·추가 진행 방지, Worker 오류 시 저장 보존이 포함됩니다. Android 빌드 작업은 API 35 에뮬레이터에서 실제 WebView 자동 진행·정지·강제 종료 후 동일 날짜 복원도 검사하고 `android-emulator-evidence`에 측정 JSON과 스크린샷을 남깁니다.

### 0.3.0 저장·업데이트·용량 관리

- 서명 공개 지문: `mobile/signing-certificate.json`. 개인 키가 아닌 공개 인증서 해시만 소스에 보관합니다. 로컬 빌드와 일반 CI 빌드는 인증서가 일치하지 않으면 중단합니다. 새 버전에서는 `versionCode`를 올립니다.
- 수동 저장은 저장 완료/실패를 표시합니다. 복원은 파일 검증·사용자 확인·DB 커밋 성공 후에만 화면의 세계를 교체하며, 실패하면 기존 저장과 화면을 유지합니다.
- 일반 기사와 연대가 명시된 이벤트는 게임 달력 기준 최근 1년만 보관합니다. 오래된 거래 기사는 상세 본문만 요약하고 선수·구단·조건 등의 구조화된 이력을 남깁니다. 1년 밖의 월간 훈련 보고서는 정리합니다. 날짜가 불명확한 옛 데이터는 추측해서 지우지 않습니다.
- 선수·통산·수상·우승·부상 이력과 경기/투구별 기록은 이 정책으로 삭제하지 않습니다. 따라서 기사 정리만으로 전체 저장 용량을 제한할 수는 없습니다. 장기 기록 지연 로딩과 실기기 메모리 측정은 후속 작업입니다.
- 저장 관리에서 앱 데이터/남은 공간을 확인할 수 있습니다. 임시 백업 정리는 7일이 지난 앱 내부 `cache/backups/*.json`만 대상으로 하며 외부 백업과 게임 DB는 유지합니다.
- 내보내기/가져오기의 네이티브 브리지 메모리는 조각 단위로 제한합니다. JSON 직렬화·파싱과 게임 전체 상태의 메모리 비용까지 없어진 것은 아닙니다. Android가 프로세스를 종료하면 마지막 완료 커밋으로 복구합니다.

기존 무작위 서명 시험판을 옮길 때는 `scripts/Update-Android-Trial.cmd`를 Windows에서 실행합니다. 실행 중인 에뮬레이터 1대와 새 APK를 선택하면 먼저 개인 저장·기존 APK를 PC에 백업하고 검증합니다. 서명이 다를 때만 `YES` 확인 후 교체·복원합니다. 교체 실패 시 기존 APK와 저장 복원을 시도하며 PC 백업은 삭제하지 않습니다. 게임을 먼저 직접 삭제하지 마세요.

CI의 정상 배포에는 `ANDROID_SIGNING_KEYSTORE`(base64), `ANDROID_SIGNING_PASSWORD`, `ANDROID_SIGNING_ALIAS` 세 Secrets가 필요합니다. 현재 연결된 GitHub 통합은 Secrets 쓰기를 HTTP 403으로 거부하므로 소유자가 한 번 등록해야 합니다. 소유자 계정으로 인증된 GitHub CLI에서 `node scripts/register-signing-secrets.mjs /private/signing.json owner/repo`를 실행할 수 있습니다. 비밀 값은 stdin으로 전달하며 로그·명령 인수로 출력하지 않습니다.

`verify_only=true` CI는 임시 인증서로 같은 키의 낮은 버전 → 새 버전 덮어 설치·백업을 시험합니다. 이 모드의 APK는 배포 아티팩트로 올리지 않습니다. 실제 개인 키는 소유자에게 별도로 인계하고 최소 두 곳에 오프라인 백업해야 합니다.

### 최종 흐름 확인

[Android 검증 실행](https://github.com/lgw11124639-cell/BASEBALL-EMPIRE/actions/runs/41599254105)에서 실제 시스템 파일 저장 창의 JSON 내보내기, 파일 선택과 확인 창을 거친 복원, 같은 인증서의 버전 코드 2→3 덮어 설치, 강제 종료/재실행, 기존 개인 데이터 아카이브를 새 설치에 스트리밍 복원한 후 같은 날짜의 이어하기를 확인했습니다. 프로·아마추어 유망주 탭도 실제 WebView 터치로 확인했습니다. 최종 APK는 소유자용 유지 키의 공개 인증서 지문과 일치하는지 별도로 검증합니다. 이 에뮬레이터 검사는 verify_only 임시 인증서를 사용하며 개인 배포 키를 CI에 노출하지 않습니다.

웹 2.3.15와 모바일 공통 유망주 화면은 후보마다 과거 시즌 전체 명단을 재조회하던 코드를 시즌별 한 번의 읽기로 변경했습니다. 300명/21시즌에서 6,300회에 해당하던 명단 읽기를 21회로 제한하는 회귀 검사, 웹 서버 모드의 21시즌 화면, 모바일 화면 전환 검사를 통과했습니다. 읽을 수 없는 과거 데이터가 있으면 목록 오류를 표시하고 다른 메뉴 이동은 유지합니다.

### 0.4.0 구장 중계

- 웹과 앱에서 공통 구장 화면, 투수·타자 카드, 이닝 이동, 투구별·타석별 재생을 제공합니다.
- 투구 위치는 저장된 좌표만 표시합니다. 타구 방향·수비 배치는 도식이며 실제 낙하지점 또는 선수 이동 좌표가 아닙니다. 위치가 없는 옛 기록에는 미기록 안내를 표시합니다.
- 구장 배경은 내장 SVG로 네트워크 연결 없이 표시합니다. 중계 종료 시 재생 타이머와 크기 관찰자를 해제합니다.
- 앱 버전 0.4.0 / versionCode 4. 유지된 서명 인증서로 0.3.0 위에 업데이트할 수 있습니다.

### 0.4.1 공·수비·주루 연출

- 투수에서 스트라이크존까지 공이 이동하며, 도착한 뒤 투구 마커와 판정을 표시합니다. 타구·포구·송구·주자 이동은 저장 결과를 바탕으로 재현합니다. 이동 경로와 동작은 실제 추적 좌표가 아닌 연출입니다.
- 기록에 있는 주자 ID와 전후 베이스 상태로 이동을 연결합니다. 득점 주자를 구별할 수 없는 옛 기록에서는 특정 선수의 홈인 경로를 만들지 않습니다.
- 수비수·주자 이름, 수비 화면 패널 숨김, 움직임 줄이기 설정을 지원합니다. 애니메이션 프레임은 재생 때만 요청하며 이닝 이동·종료 때 취소합니다.
- 버전 0.4.1 / versionCode 5, 기존 유지 서명 인증서를 사용합니다.

### 0.4.2 점·실명과 베이스 커버

- 투구 화면은 마운드 뒤에서 홈플레이트를 향하는 별도 구도이며 사람 캐릭터 없이 공 무브먼트·스트라이크존을 표시합니다. 타격·도루·견제 때는 이름 붙은 점들이 움직이는 수비 화면으로 전환합니다.
- 수비 이름은 해당 경기 Positions 스냅샷을 우선하며 한국어·영문 포지션과 교체 선수의 승계 위치를 지원합니다. 이름이 없는 옛 자료에는 미기록을 표시합니다.
- 1루수 직접 베이스 터치, 투수 1루 커버, 병살 커버, 외야 중계 수비를 구분하며 송구 도착 시 받는 점이 목적지에 있도록 이동 계획을 공유합니다. 도루 포수 송구·견제·런다운은 경기 기록의 주자 ID와 성공·실패를 재현합니다. 경로는 추적 좌표가 아닌 연출입니다.
- 드문 견제·런다운을 실제 하루 경기 계산에서만 판정·저장합니다. 견제 아웃은 타석·투구 수·도루 실패 수를 올리지 않고 팀·투수의 아웃을 반영합니다.
- 앱 0.4.2 / versionCode 6, 유지 서명으로 업데이트합니다.

### 0.4.3 중계 화면·타자·포수

- 불투명 스트라이크존, 상단 중앙 구속·구종, 왼쪽 현재 타석 투구 기록을 표시합니다. 중복 요약·이닝 이동·결과 건너뛰기·타석 모드 버튼을 제거하고 진행·정지, 1·2·3배와 하이라이트 옵션을 둡니다. 전체 기록은 접어 둡니다.
- 선을 남기지 않고 공만 움직입니다. 투구 마크와 도착점은 같은 SVG 좌표를 사용하며 크기 변경 때 진행 중 경로도 갱신합니다. 정지는 타이머와 공 동작을 함께 멈추며 재개 시 이어집니다.
- 투구폼별 릴리스 위치, 구종별 수평 변화·낙차·너클 흔들림, 좌우 투구 반전을 연출합니다. 새 타석 기록에는 투수 손·폼과 타자 손을 보존합니다.
- 투구 화면 타자·포수는 별도 SVG 동작이며 수비 화면은 실명 점을 유지합니다. 저장된 스윙 판정만 스윙하고, 포수 리드를 표시합니다. 실제 프레이밍으로 가장자리 루킹 판정이 난 투구에는 프레이밍 표기를 기록합니다. 투구 판정이나 경기 결과를 시각 연출로 바꾸지 않습니다.
- 하이라이트는 득점·안타·장타·주요 수비·주루를 선택하며 생략한 장면의 점수·투구 수·베이스 상태도 반영합니다.
- 0.4.3 / versionCode 7, 유지 서명 인증서로 업데이트합니다.

### 0.4.4 고정 글러브·현재 궤적·소리

- 타자·포수 몸과 프레이밍 연출을 제거하고, 원래 크기의 불투명 존 위에 고정 글러브만 표시합니다. 새 투구에는 실제 리드 목표 좌표를 보존하며 옛 기록은 몸쪽·바깥쪽과 타자 손을 기준으로 표시합니다. 목표 정보가 없으면 글러브를 숨깁니다.
- 현재 공이 지나간 만큼의 궤적만 표시하며 다음 투구 때 교체합니다. 공 도착 마크와 궤적은 같은 좌표를 씁니다. 타격 임팩트와 홈런 강조는 실제 기록에 맞춰 재생하고 움직임 줄이기를 존중합니다.
- 소리 옵션은 타격음·아웃음·홈런 효과음과 스트라이크·볼·아웃·홈런 콜을 켭니다. 효과음은 Web Audio로 합성합니다. 음성은 Android에 설치된 한국어 오프라인 TTS(웹은 설치된 로컬 한국어 음성)만 사용합니다. 지원 음성이 없을 때 효과음은 계속 동작합니다.
- TTS는 소리를 켜고 중계를 시작할 때 초기화하며 정지·닫기·백그라운드 전환 시 음성을 중단합니다. 음성 대기열은 최신 콜만 유지합니다. 네트워크 권한이나 음성 서버를 추가하지 않습니다.
- 0.4.4 / versionCode 8, 유지 서명 인증서로 업데이트합니다.
