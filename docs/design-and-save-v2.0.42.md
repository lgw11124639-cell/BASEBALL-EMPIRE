# 2.0.42 · One UI stylesheet, refreshed management and broadcast screens

The page previously loaded 34 stylesheets plus 15 inline theme blocks, with additional unused legacy CSS present in the repository. All 35 previous CSS files are removed. `index.html` now loads only `ui.css`; it contains the current shared components and responsive layouts. Superseded identical declarations were removed while preserving selector priority and conditional rules. The old front-office rules and old replay height/layout rules were explicitly retired. The stylesheet is the editable source; there is no runtime theme override stack or build dependency. Change existing component rules in this file rather than adding override stylesheets. CSS parsing/consolidation used temporary PostCSS and Lightning CSS tools, with Safari 15.6 and Chrome 110 output targets. CSS details are in `css-v2.0.42-cleanup.json`.

Front office now presents strategy, finances, facilities and people in distinct sections. Finance has readable balance and annual totals, horizontal monthly tables, expandable transactions and explicit empty states. Facility cards show existing investment levels; management and coaching staff have separate identity, contract and salary fields. Existing financial calculations, staff contracts and automatic investment behavior are retained.

Broadcast now has a navy match scoreboard, correct club crests, a scrollable inning board, clear inning/count/base and pitch-zone panels, readable newest-first commentary, lineups and fixed playback controls. Old fixed scoreboard heights were removed, and browser assertions check that scores, crests and labels fit inside the scoreboard. Playback, older-passage scroll preservation, speed controls and final scores retain the existing saved-game logic. Opening a replay locks the underlying page; closing restores its scroll setting and focus. International matches use their actual country labels rather than fictional club crests.

Title/club selection, account login/signup, award candidates and official awards, postseason stages, minor standings and results, club sheets and shared secondary text were aligned with the current navy/teal/light-card design. Account presentation no longer embeds the previous inline theme. Missing award and finance records have explicit empty states. Player detail retains fixed dimensions and no automatic vertical scrolling on tab changes.

## Save preparation

Production before/after inspection found that the daily `faLastRegistrationCountedDateByYear` marker was stored in player base shards, causing unchanged biographies and contract histories in those shards to be uploaded again. The marker now travels with existing live counters; all dates, including old years, remain intact. Large `leagueOffice` data uses the existing lossless auxiliary gzip mechanism. Exact serialized-content comparisons, revision checks, retry behavior and historical edits are preserved. No daily simulation, statistics, contracts or game histories are skipped or shortened.

`cloud-fa-registration.test.cjs` exercises legacy loading, complete round trips, a failed migration upload and retry, and unchanged static contract shards during daily registration. Its long-history fixture produced 120,117 bytes before vs 18,233 bytes after for one daily PATCH. The synthetic preparation benchmark updates all 2,600 players' registration markers and is intentionally a stress case: its savings are not a prediction for an individual user's save. Actual-production-day and synthetic benchmark outputs are adjacent JSON files. These measure local preparation/PATCH bytes, not real-account upload latency or server time. The first save after updating may rewrite old shard placement; subsequent daily saves benefit from the finer split.
