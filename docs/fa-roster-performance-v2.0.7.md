# v2.0.7 FA 일정·선수단·속도

## FA 협상 일정

FA 자격 정산일에는 신청 선수의 시장 등록과 협상 준비만 처리한다. 선수별 최초 검토는 등록 후 1~21일, 후속 검토는 5~14일 간격으로 분산한다. 이는 시장 검토 시간을 단순화한 모형이며 하루 계약 인원을 강제하는 정원은 아니다.
실제 제안·거절·수락·정산은 검토일에 기존 협상 로직을 실행한다. 즉시 계약을 일괄 체결하는 경로와 전체 미계약 선수를 같은 14일 배수 날짜에 검토하던 경로를 제거했다.
시장 개시는 기존 포스트시즌 종료·계약 처리 기간 조건을 유지한다. 미계약 선수는 다음 시즌에도 협상할 수 있으며 강제로 계약하거나 FA 종료일에 소속팀으로 되돌리지 않는다.

검토 일자는 게임 달력의 ISO 날짜로 저장한다. 12월 말 일정이 다음 해로 넘어가도 1월 1일에 모두 실행되지 않는다. 기존 미계약 자료에는 날짜를 새로 배정하며, 이미 체결된 계약은 변경하지 않는다.
FA 화면에는 준비/거절 이유와 다음 검토일을 표시한다.

20명·10개 구단 시나리오에서 등록일 계약 0건, 이후 여러 날짜에 계약이 체결되는 것을 검증했다. 같은 날짜 재실행과 연도 변경에서도 중복 정산되지 않는다.

## 선수단

1군 투수·1군 타자·2군 투수·2군 타자를 별도 명단으로 표시한다. 육성과 입단 예정 신인도 유지한다.
선수단, 투수/타자, 포지션, 이름/등번호 검색, 정렬을 조합할 수 있다. 이름순 정렬과 필터 초기화를 추가했다. 투수/타자와 포지션 선택이 충돌하면 관련 선택을 조정한다.
필터 상태를 유지하고 결과에 맞지 않는 빈 구분은 숨긴다. 필터 결과 갱신은 명단 영역만 바꾸므로 검색 입력의 포커스를 유지한다. 선수 클릭/키보드 상세 보기와 기존 타순·선발진/엔트리 화면은 유지한다.
능력치·오버롤 숫자를 노출하지 않는다.

## 성능

CPU 프로파일에서 감독 명단 구성 시 동일 선수의 최근 10경기 탐색과 선발 평가가 반복되는 것을 확인했다.
최근 경기 합계는 해당 계획의 불변 경기 목록 범위에서 재사용하고, 명단 구성에 필요한 평가는 그 구성 작업에서만 캐시한다. 반환하는 평가 함수는 경기 중 피로·기록 변화를 계속 반영한다.
타석 안에서도 변하지 않는 투수 스타일·구종별 타자 상성은 해당 타석에서만 재사용한다. 새 타석/교체 시 새로 계산한다.

측정값은 `performance-v2.0.7.json`에 기록한다. Node.js 22.23.4에서 공개 v2.0.6 커밋 `f685bda`와 수정본을 각각 새 프로세스로 순차 측정했다. 720경기의 전체 집계와 실제 일별 진행 3일의 직렬화된 상태 해시가 일치해야 성능 비교를 인정했다.
경기 계산 벤치마크와 실제 일별 서비스(2군·아마추어·육성 등)의 시간은 구분한다. 후자는 초기 생성 비용이 포함된다. 브라우저 렌더링·클라우드 저장 통신 시간은 이 수치에 포함되지 않는다. 자동 진행에서 저장을 건너뛰거나 경기 수/규칙을 줄이지 않았다.

## 검증

- 기존 검사와 새 검사를 합친 테스트 40개, 실제 720경기 검증.
- 10개 구단 FA 등록/일별 검토/거절/체결/재정 검증, 12월~1월 경계와 기존 미계약 자료의 일정 배정 검사.
- 감독 계획 캐시가 경기 중 피로·성적 변화를 가리지 않는 검사.
- Playwright/Chromium의 1920×1000 및 390×844 화면에서 선수단 조합 필터·검색·초기화·정렬·가로 넘침과 기존 중계 스크롤 확인.
- 선수 등록·계약·통산·경기 자료는 초기화하지 않았고 클라우드 전송 코드는 변경하지 않았다.
