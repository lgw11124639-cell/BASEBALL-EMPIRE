# v2.0.16 CI 회귀 복구

## 확인한 기준

2026-11-01 인수인계에 따라 원격 main 4d228717ae005698078db3de1b32215fd856d91d에서 시작했다. 이전에 로컬에서 진행하던 서버/포스트시즌 변경은 /workspace/BASEBALL-EMPIRE의 별도 미통합 상태로 보존하고, 최신 main의 오류는 별도 작업 디렉터리에서 재현했다. 기존 신규 기능을 다시 적용하지 않았다.

확인한 원격 실패: Release Gate 41217109825, Baseball regression checks 41217109957. 로컬 전체 48개 진입점을 실행했을 때 4개가 실패했다.

- day-save.test.js: advanceSeason의 새 화면 갱신 경로가 autoSeasonRunning을 읽지만 테스트 모의 환경에 변수가 없어 ReferenceError 발생. 정상 진행 반환값이 false가 되어 실패했다.
- release-smoke.test.js: 내부에서 실행한 day-save.test.js 실패로 함께 실패했다.
- fa-late-settlement.test.cjs: 현재 계약은 startYear=2028로 맞았지만 years=2, endYear=2029였다. 종료 연도 검증이 실패했으며 시작 연도를 반복 수정할 문제가 아니었다.
- fa-negotiation.test.cjs: 최근 출전 근거와 경력 경기 수가 없는 선수에게도 i<=1 예외로 2년 보장을 허용하던 같은 로직 때문에 실패했다. 원격 CI는 앞선 실패에서 중단돼 이 오류까지 도달하지 못했다.

## 변경

- faPlayerProjection에서 출전/경력 근거 없이 무조건 2년을 허용하는 예외를 제거했다. 최근 표본이나 실제 경력 근거가 있으면 기존 다년계약 판단을 유지한다. 기존 체결 계약은 변경하지 않는다.
- 신규 FA의 시작 시즌은 원래 시장의 다음 시즌을 최소 기준으로 하며, 이미 시간이 더 지난 미계약자는 현재 계약 가능 시즌보다 과거로 소급하지 않는다. 시즌 전환 때 연도가 두 번 증가하지 않고, 이전 시장의 지연 계약도 현재 시즌부터 반영한다.
- day-save 모의 환경에 실제 의존성과 제어 가능한 타이머를 제공한다. 기존 5개 시나리오의 검증을 유지하고 정상 진행, 엔진/저장 실패 시 중첩 기록 복구, 정규/포스트시즌 지연 화면 갱신, 자동 진행, 관전 날짜 유지 및 다음 버튼 1회 증가, 중복 요청 차단의 총 11개 시나리오로 확장했다.
- 신규 FA 계약 연도 테스트는 6가지 시점 × 1년/3년 계약 총 12건과 보장 연봉/계약 이력/FA 행사 횟수/계약 만료/근거 있는 복귀 선수를 확인한다. 워크플로에도 추가했다.
- 버전/캐시 키를 v2.0.16 / 20261101-ci38로 맞췄다. 기존 cloud-only 모듈도 최신 코드에 맞게 새 캐시 키를 사용한다.

## 검증

Node v22.23.4로 모든 *.test.js 및 *.test.cjs 49개 진입점 통과. 실제 720경기 검사를 포함한다. pitching-awards, day-save, fa-late-settlement, release-smoke와 두 워크플로가 실행하는 항목을 모두 확인했다. 정상 검증을 삭제하거나 기대 계약 연도를 바꾸지 않았다. 반복 오류를 사라지게 하기 위한 예외 처리로 게임 실패를 숨기지 않았다.

기존 클라우드 저장이나 서버 DB를 읽거나 수정하지 않았다. 이 변경의 서버 최적화 실제 반영, 대형 부상의 장기 재활 및 공인구 추가 기능은 별도 검증/작업이 필요하다. 원격 CI 결과와 배포 파일 검증은 커밋 후 별도로 확인한다.
