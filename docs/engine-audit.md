# 실제 경기 엔진 검증 — v2.0.2

기준 커밋: v2.0.1 `ede05110c53355e07d0679618312082141c23cd3`.
검증 런타임: Node.js 22.23.4. 클라우드 저장 데이터는 읽거나 수정하지 않았다.

## 구조와 실제 호출 경로

- `index.html`: 정적 웹/PWA 진입점, CSS 및 ES 모듈 로딩.
- `app.js`: 선수 생성(`world`, `ensureProfile`), 스케줄, 경기, 계약, 기록, UI.
- `cloud-only.js`: 현 게임에서 사용하는 로그인/클라우드 저장 전송 계층.
- `cloud-save.js`: 별도 opt-in 저장 구현. 현재 `app.js`의 import 대상은 아니다.
- `sw.js`, `update.js`, `version.json`: PWA 갱신과 버전 표시.
- `tests/`: Node 내장 모듈 기반 테스트. 별도 패키지 설치/번들 빌드 없음.
- `.github/workflows/`: 회귀 검사와 릴리스 검사.

1군: `simulateLeagueDay → scheduledPairs → inningClub → managerPlan → createInningClub → runBaseballInnings → playHalf`.
2군: `simulateSharedMinorGame → minorInningClub → runBaseballInnings → playHalf`.
국가대표: `internationalSharedGame → runBaseballInnings → playHalf`.
타석에서는 `pitchingArsenal`, `simulatePitchLocation`, 구종/카운트별 스윙·헛스윙 판정, `resolveBattedBall`의 타구 속도·각도·수비 판정을 사용한다.
투수 기록은 `finishPitchers`, 타자 기록은 경기 전후 누적값 차이로 박스스코어를 만든다.

## 실제 720경기 검증

```sh
cd /workspace/BASEBALL-EMPIRE
export PATH=/workspace/.baseball-tools/node-v22.23.4-linux-x64/bin:$PATH
BALANCE_REPORT=/tmp/baseball-balance.json node tests/league-balance.test.cjs
```

`tests/helpers/game-context.cjs`는 클라우드/브라우저 초기 진입만 제외하고 실제 `app.js`를 로드한다.
시즌 검증은 `simulateLeagueDay`의 실제 1군 경기 처리 구간을 실행하며 타석/타구/투수/라인업/스케줄 결과를 모의 함수로 대체하지 않는다.
700명 초기 선수단, 팀당 144경기, 총 720경기. 일별 투수 회복과 부상 일수 감소를 적용한다.
이 실험은 이적·육성·2군 동시 진행·국제대회·실제 저장 통신을 제외한 **초기 선수단의 1군 엔진 검증**이다. 사용자의 진행 중인 클라우드 시즌과 같다고 해석하면 안 된다.

## 확인하고 수정한 오류

`playHalf`가 타구 판정에 쓸 마지막 투구 위치를 선택적 중계 기록(`bePlate.pitchSequence`)에서 가져왔다.
따라서 동일한 선수·기존 핫존 기록·난수에서도 중계를 기록하지 않는 경로는 투구 위치를 잃었다.
이제 타석 내부 `lastPitchLocation`을 직접 전달한다. 공유 엔진 변경이므로 모든 경기 종류에 적용된다.
실제 엔진을 불러온 독립성 회귀 검사에서 기존 코드는 seed 3으로 실패했고, 수정 후 seed 1~30이 모두 통과했다.
1군은 이미 중계를 기록하므로 이 수정 전후 위 시즌 수치가 동일한 것은 예상되는 결과다.

기존 단위 테스트 3개의 VM 문맥에서 새 `resolveBattedBall` 의존성이 빠져 있었다.
누적/시나리오 검사는 결정적 타구 fixture를 명시하고, 종합 검사는 실제 타구 함수를 로드하도록 수정했다.
새 시즌 검사가 실제 엔진 경로를 추가 검증한다. 기존 단언은 유지했다.
업데이트 위젯에 남아 있던 v2.0.0 상수도 v2.0.2와 일치시키고 HTML/업데이터/매니페스트 일치 검사를 추가했다.

## 아직 해결하지 않은 밸런스와 후속 순서

- 이 표본은 .260 및 ERA 4점대에 미치지 못한다. 리그 평균을 사후 보정하거나 경기 점수를 강제로 바꾸지 않았다.
- `resolveBattedBall`의 2루타 판정은 99/103mph 문턱에 의존한다. 2루타 608개와 3루타 214개의 분포를 추가 분석해야 한다.
- 실제 투구 경로에서는 사구를 종결 결과로 만들지 않는다. 따라서 표본의 사구가 0이다. KBO 사구·스윙·스트라이크존 규칙을 반영하는 별도 수정이 필요하다.
- 다음 엔진 작업은 타구 종류별 분포와 서로 다른 시즌 seed 검증, 타구 회수·송구·주루 시간에 근거한 장타 판정 개선이다. 초기 선수단 한 시즌만으로 모든 저장 게임의 밸런스를 일반화하지 않는다.
- 이후 일반 연봉/FA/외국인 계약의 표시·갱신 검증, 브라우저 경기 진행과 저장 성능 측정을 진행한다.
- 클라우드 저장 형식과 계약 데이터, 선수 능력치 UI는 이번 변경 대상이 아니다.
